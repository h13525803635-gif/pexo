# Case 16310225617 问题汇总

## 一、结论摘要

项目 `16310225617` 存在两类相互关联、但发生在不同链路的问题：

1. 制作方案规划了三段视频，但第一批生成任务只提交了第 1 段和第 3 段。第 2 段是在后续补救过程中才生成的，同时第 3 段还经历了多次重试和模型切换。
2. Langfuse 中记录的最终后台拼接并不存在 `1分19秒` 的视频素材。最终选用的三段源视频实际时长分别约为 `7.04秒`、`8.04秒` 和 `7.04秒`。因此，时间线中出现 `1分19秒`，以及视频播放十秒后长期静止，来自下游编辑器或时间线持久化链路使用了错误时长、旧素材版本或错误素材清单。

后台最终拼接明确包含第 1 段。如果用户看到的编辑器时间线或交付成片缺少第 1 段，那么遗漏发生在时间线保存、恢复或展示阶段，而不是 Langfuse 记录的最终 `concat` 调用阶段。

## 四、根因分析

### 4.1 根因一：生成任务没有与脚本分段进行完整性校验

第一批生成漏掉第 2 段，但系统仍然继续执行。后续通过临时补生成和多次重试恢复素材，而不是重新核对完整的三段制作方案。

这会造成两个问题：

- 不同分段的生成状态和版本不一致。
- 编辑器、拼接服务和交付层可能分别引用不同批次的 Asset。

### 4.2 根因二：预期十秒没有传递到视频生成参数

第 2 段最终生成调用明确使用了：

```json
{
  "name": "rome_egypt_seg2_reveal_k2",
  "duration": "8"
}
```

模型最终返回 `8.041667秒`，与请求的 8 秒一致。

因此，第 2 段没有达到预期十秒，不是视频模型少生成了，而是上游在调用生成模型前就把时长设置成了 8 秒。这属于制作方案到生成参数之间的传递错误。

### 4.3 根因三：编辑器时间线时长与媒体真实时长不一致

Langfuse 中没有任何最终选用素材的时长是 1 分 19 秒。后台最终拼接的预期总时长也只有约 22.13 秒。

因此，用户看到的 `1分19秒` 不可能来自本次实际视频生成参数或最终 `concat` 参数。

最符合现象的下游故障路径是：

```text
时间线 Clip 被写入错误或过期的时长
  → 真实视频在约 8 秒时播放结束
  → 播放器继续显示最后一帧
  → 剩余时间看起来一直静止
```

错误时长可能来自：

- 把项目总时长错误写入单个 Clip。
- 秒、毫秒、帧或时间码之间转换错误。
- 重试生成后仍然读取旧版本素材的时间线记录。
- 编辑器恢复项目时，用旧 Asset ID 和新时长进行了错误组合。
- 生成任务耗时或其他非媒体字段被误当成视频时长。

### 4.4 根因四：缺少最终成片级别的 QA

Agent 在拼接前探测了三个输入素材，但没有对最终成片执行：

- 最终时长校验。
- 首帧和分段边界抽帧检查。
- 第 1 段是否实际可见的检查。
- 尾部连续重复帧或静帧检测。

因此，即使时间线展示、交付 Asset 或拼接结果存在问题，当前交付门禁也无法发现。

## 五、解决方案

### 5.1 建立唯一的分段清单

在生成前建立一份唯一的分段清单，并让生成、重试、拼接、数据库和编辑器全部使用同一份数据：

```json
[
  {"sequence_id": 1, "asset_id": "a_Nooqypp", "duration": 7.041667},
  {"sequence_id": 2, "asset_id": "a_xR7ZktL", "duration": 8.041667},
  {"sequence_id": 3, "asset_id": "a_hmYRKAe", "duration": 7.041667}
]
```

重新生成某一段时，必须根据同一个 `sequence_id` 原位替换 Asset，不能追加成一个无法与原分段对应的新时间线项目。

### 5.2 增加拼接前完整性门禁

进入 assembly 之前必须满足：

```text
计划中的 sequence_id 集合
==
成功生成的 sequence_id 集合
```

任何一个分段缺失，都必须停止拼接。这条规则可以直接阻止本项目第一批漏掉第 2 段后继续执行。

### 5.3 建立时长传递和校验契约

- 用户确认的目标时长必须原样传递到 `video_generate.duration`。
- 生成完成后，以 `media_probe.derived.video_playable_seconds` 作为素材真实时长。
- 时间线 Clip 时长与实际媒体时长相差超过 `0.1秒` 时，默认阻止保存和交付。
- 只有明确配置了循环、变速、裁切、冻结尾帧或停留设计，才允许时间线时长超过源视频时长。
- 禁止使用生成耗时、项目总时长、UI 文本或旧 Asset 时长推导当前 Clip 时长。

### 5.4 完善时间线持久化字段

每个时间线 Clip 必须同时保存并校验：

```text
sequence_id
asset_id
asset_version
source_duration_seconds
timeline_in_seconds
timeline_out_seconds
explicit_end_behavior
```

时间线槽位长于源视频时，系统必须要求明确选择结束行为。不能默认无限显示最后一帧。

### 5.5 增加最终交付 QA

最终拼接完成后必须：

1. 对最终 Asset 再执行一次 `media_probe`。
2. 将最终时长与分段清单的时长总和进行比较。
3. 在 `0秒`、每个分段边界和结束前一秒抽帧。
4. 确认开头画面属于第 1 段。
5. 检测连续重复帧，非明确设计的长静帧必须阻止交付。
6. 再次核对最终分段数量、顺序和 Asset ID。

## 六、最终诊断

本项目的第一批生成任务确实没有完整执行三段制作方案，且预期十秒的第 2 段在调用视频模型前被错误设置成了八秒。

后续后台拼接最终选用了三段有效素材，顺序正确，并明确包含第 1 段。三个素材的实际总时长约为 22.13 秒。

因此，用户看到的“缺少第一段”“第二段显示 1 分 19 秒”和“十秒后长期静止”，指向另一处独立的时间线保存或编辑器恢复问题：下游没有使用最终拼接所采用的统一 Asset 清单和媒体真实时长，并在源视频播放结束后持续显示了尾帧。缺少最终成片时长与视觉 QA，使该问题最终进入了交付结果。
