# Pexo 视频模糊问题根因汇总

本文汇总了三个 Pexo 项目在 Langfuse 调用链中暴露出的「画面糊 / 细节发软」问题根因与修复方案。

- `95891435564`
- `93798093580`
- `06994555780`

分析依据来自本地拉取的 Langfuse observation 与关键工具回包：

- `analysis/langfuse-data/cases/95891435564/observations.json`
- `analysis/langfuse-data/cases/93798093580/observations.json`
- `analysis/langfuse-data/cases/93798093580/final-key-details.json`
- `analysis/langfuse-data/cases/06994555780/observations.json`
- `analysis/langfuse-data/cases/06994555780/key-details.json`

## 总览结论

三个项目都表现为「糊」，但根因并不一样：

| 项目 | 主要根因 | 优先解决方案 |
| --- | --- | --- |
| `95891435564` | 源画面由 AI 视频模型生成，本身就偏软。尤其是办公屏幕、dashboard、白板、小字等信息密集画面。最终 1080p 高质量渲染参数正常。 | 人物、办公室、镜头运动继续用视频生成；UI、文字、dashboard、白板内容改成 HTML / SVG / 设计稿叠层。 |
| `93798093580` | 1080p 源视频 + 1080p HTML 画布最终导成 4K，属于「假 4K 放大」。多轮重渲染也进一步损失细节。 | 要么按真实 1080p 输出；要么从源素材、HTML 画布、贴图、最终渲染全链路真 4K。 |
| `06994555780` | Seedance 源片段是 720p，被放进 1080p 成片；最终成功渲染还用了 `quality: standard`。 | 源片段必须直接生成 1080p 或更高；修 lint 让 `quality: high` 成功；数据屏/UI 改成清晰叠层。 |

## 项目 `95891435564`

### 关键证据

最终视频：

- 输出文件：`Copilot_Momentum_Final_Cut.mp4`
- 最终 asset：`asset://a_bXDQgj5`
- 分辨率：`1920x1080`
- 帧率：`30fps`
- 视频码率：约 `9.52 Mbps`
- 渲染质量：`high`

这说明最终导出容器和编码参数本身没有明显问题，不能简单归因于「导出压缩太狠」。

生成链路：

- 主视觉素材来自 `video_generate`
- provider / model：`seedance` / `doubao-seedance-2-0-260128`
- mode：`reference2video`
- prompt 主要描述办公会议、白板、dashboard、笔记本电脑、屏幕和数据工作流

容易导致画面发软的 prompt / 设计因素：

- `soft diffused natural office lighting`
- `organic film-like texture`
- `indistinct writing`
- dashboard、白板、电脑屏幕、办公 B-roll 等都直接交给视频模型生成

### 根因

这个项目不是最终导出低清，而是**源画面本身信息量不足**。

视频模型可以生成「像 dashboard」「像白板」「像电脑屏幕」的画面，但不擅长稳定生成清晰、可读、信息密集的 UI 和文字。最终高质量渲染只能保留这些源素材的状态，不能把源素材里不存在的细节补回来。

换句话说：最终是一个正常的 1080p 高清文件，但里面放进去的是偏软的 AI 生成画面。

### 解决方案

1. Seedance 只负责人物、办公室、环境、镜头运动和氛围画面。
2. 所有承载信息的画面改成确定性叠层：
   - dashboard UI
   - Copilot 界面
   - 白板文字
   - 图表
   - PPT / slides
   - 字幕和标签
3. 用 HTML / SVG / Figma / 截图做这些叠层，并在最终 render 阶段合成。
4. 需要清晰度时，少用会主动软化画面的词：
   - 避免：`soft`、`diffused`、`film-like texture`、`indistinct writing`
   - 倾向：`sharp focus`、`crisp edges`、`large legible text only`
5. 每个生成片段后增加质检门槛：
   - `media_probe`
   - 抽代表帧
   - 屏幕、脸、前景主体明显发软时，不进入最终 assembly

## 项目 `93798093580`

### 关键证据

原始 / 主源视频：

- asset：`asset://a_uxquaVs`
- 分辨率：`1920x1080`
- 帧率：`30fps`
- 视频码率：约 `8.52 Mbps`
- 时长：约 `61s`

中间 1080p 成片 asset：

- asset：`asset://a_iLMbyz1`
- 分辨率：`1920x1080`
- 帧率：`30fps`
- 视频码率：约 `10.37 Mbps`

最终渲染：

- 输出文件：`pexo_brand_film_4k.mp4`
- 最终 asset：`asset://a_LWuqhUK`
- `submit_render` 使用：`output_resolution: landscape-4k`
- `submit_render` 使用：`quality: high`

HTML 画布证据：

- 多次 composition 使用 `data-width="1920"`、`data-height="1080"`
- 背景源视频也是 1080p

### 根因

最终文件名和输出参数是 4K，但生产链路并不是真 4K：

- 源视频：1080p
- HTML composition 画布：1080p
- overlay / preview：1080p
- 最终导出：4K

这会得到一个「4K 壳子、1080p 信息量」的视频。文件分辨率可以是 4K，但画面细节仍然只有 1080p，被放大后自然显得软。

此外，链路里出现了多个连续版本：`v2`、`v3`、`dialogue`、`typewriter`、`v5`、`v6`、`4k`。如果每次都基于上一个视频继续渲染，就会产生多代重编码，进一步损失纹理、边缘和暗部细节。

### 解决方案

1. 如果源素材是 1080p，就按 1080p 输出，不要导假 4K。
2. 只有全链路都是真 4K 时才导 4K：
   - 原始视频是 4K
   - HTML 画布是 `3840x2160`
   - overlay、图片、截图、文字排版都按 4K 设计
   - 最终 render 也是 4K
3. 避免多代重渲染：
   - 不要 `v2 -> v3 -> v5 -> v6 -> 4k`
   - 始终回到原始源视频，一次性叠加所有最终图层
4. 信息卡、字幕、prompt box、标签等保留为 HTML / 矢量图层，在最后一轮 render 里生成。

## 项目 `06994555780`

### 关键证据

视频生成：

- 主片段来自 `video_generate`
- provider / model：`seedance` / `doubao-seedance-2-0-260128`
- mode：`reference2video`
- 示例片段：
  - `seq1_container_port`
  - `seq7_nearshoring_factory`
  - `seq8_digital_supply_visibility`

源片段 probe：

- 生成源片段分辨率：`1280x720`
- 帧率：`24fps`
- 码率范围：约 `3.8 Mbps` 到 `5.6 Mbps`
- 单段时长：约 `15s`

合成证据：

- 初始 HTML 使用 `data-width="1280"`、`data-height="720"`
- 后续才向 1080p 输出调整

最终成片：

- 输出文件：`Supply_Chain_Disruptions_-_Educational_Video.mp4`
- 最终 asset：`asset://a_uW24zda`
- 分辨率：`1920x1080`
- 帧率：`24fps`
- 时长：`241s`
- 视频码率：约 `11.44 Mbps`
- 最终成功 render 使用：`quality: standard`

曾尝试过 `quality: high` 渲染，但 lint 失败，问题包括：

- `MEDIA_MISSING_DATA_START`
- `OVERLAPPING_CLIPS_SAME_TRACK`

### 根因

最终 1080p 成片主要由 720p 生成片段组成。最终文件是 1080p，但源画面细节只有 720p，被放大到 1080p 后会显得糊。

问题还被以下因素放大：

- 源片段本身是 AI 视频生成
- 内容包含控制室、地图、dashboard、图表、大屏等信息密集场景
- 用有限数量的 15s 片段撑起 241s 长视频，需要桥接、延展和复用
- 最终成功渲染降到了 `quality: standard`

### 解决方案

1. 源片段必须按目标分辨率生成：
   - 如果最终要 1080p，源片段至少要 1080p
   - 如果模型只能出 720p，就最终输出 720p，不要硬拉到 1080p
2. 修复 HyperFrames lint，让 `quality: high` 可以成功：
   - 补齐缺失的 `data-start` / `data-duration`
   - 移除同轨重叠
   - final render 前先 validate
3. 不要让视频模型生成数据屏：
   - 物流地图
   - dashboard 图表
   - shipment tracking interface
   - control-room display wall
4. 数据屏和 UI 用 HTML / SVG / 矢量 overlay 渲染。
5. 从第一版就统一画布：
   - 目标 1080p 时，起稿就是 `1920x1080`
   - 不要先用 `1280x720`，再中途改 1080p

## 跨项目预防清单

面向容易糊的视频，交付前建议统一检查：

1. 用 `media_probe` 确认所有源片段分辨率。
2. 源片段分辨率必须不低于最终输出分辨率。
3. HTML 的 `data-width` / `data-height` 必须和最终输出一致。
4. 最终 render 默认使用 `quality: high`，除非有明确记录说明为什么不能用。
5. 不要默认把 720p 放大到 1080p，也不要把 1080p 放大到 4K。
6. 文本、UI、dashboard、地图、表格、字幕、产品卖点必须用 HTML / SVG / 设计稿叠层。
7. 避免多代视频重渲染；最终交付应回到原始素材一次性合成。
8. 最终交付前抽代表帧检查：
   - 人脸
   - 前景主体
   - 文字
   - UI
   - 高频背景细节
9. 信息承载区域如果已经变成 AI 纹理糊块，应重做，不要继续进入最终合成。

## 建议的默认生产策略

AI 视频生成适合负责：

- 氛围
- 人物
- 环境
- 镜头运动
- 情绪
- 非信息承载背景动作

确定性渲染必须负责：

- 文字
- UI
- dashboard
- 图表
- 地图
- 品牌 / 产品卖点
- 字幕
- 白板
- PPT / slides

最稳的生产模式是：

> 用 AI 生成电影感背景视频，再在最终分辨率下叠加清晰的信息图层。
