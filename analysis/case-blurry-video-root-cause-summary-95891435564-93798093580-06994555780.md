# Pexo Blurry Video Root Cause Summary

This report summarizes the blur / softness root causes for three Pexo projects investigated from Langfuse observations.

- `95891435564`
- `93798093580`
- `06994555780`

Local evidence used during analysis:

- `analysis/langfuse-data/cases/95891435564/observations.json`
- `analysis/langfuse-data/cases/93798093580/observations.json`
- `analysis/langfuse-data/cases/93798093580/final-key-details.json`
- `analysis/langfuse-data/cases/06994555780/observations.json`
- `analysis/langfuse-data/cases/06994555780/key-details.json`

## Executive Summary

The three projects all looked blurry, but for different reasons:

| Project | Primary Root Cause | Best Fix |
| --- | --- | --- |
| `95891435564` | AI-generated source imagery is inherently soft, especially office screens, dashboards, whiteboards, and small text. Final render is normal 1080p/high-quality. | Keep people/backgrounds in video generation, but render UI/text/dashboard/whiteboard content as crisp HTML or design overlays. |
| `93798093580` | 1080p source and 1080p HTML composition were exported as 4K, creating a "fake 4K" upscale. Multiple re-encodes also softened detail. | Either export true 1080p, or rebuild the whole pipeline as true 4K from source assets through HTML canvas and final render. |
| `06994555780` | Seedance source clips are 720p and were placed into a 1080p final composition; final render used `quality: standard`. | Generate source clips at 1080p+, use `quality: high`, and keep UI/data screens as crisp overlays. |

## Project `95891435564`

### Evidence

Final video:

- Output file: `Copilot_Momentum_Final_Cut.mp4`
- Final asset: `asset://a_bXDQgj5`
- Resolution: `1920x1080`
- FPS: `30`
- Video bitrate: about `9.52 Mbps`
- Render quality: `high`

This means the final render container and encoding settings were not the main cause.

Generation chain:

- Main visual material came from `video_generate`.
- Provider/model: `seedance` / `doubao-seedance-2-0-260128`
- Mode: `reference2video`
- Prompts focused on photorealistic office scenes, whiteboards, dashboards, laptops, screens, and data workflows.

Prompt/design factors that encouraged softness:

- `soft diffused natural office lighting`
- `organic film-like texture`
- `indistinct writing`
- Generic dashboards, whiteboards, laptop screens, and office B-roll generated directly by the video model.

### Root Cause

This is not primarily a final export or compression problem. The final 1080p file is technically healthy. The visible softness comes from the upstream visual source: AI-generated office footage and imagined screen/UI details.

The model can generate something that looks like a dashboard or whiteboard, but it does not reliably produce readable, sharp, information-dense UI. A high-quality render can preserve the softness, but it cannot recover detail that was never present in the source.

### Solution

1. Keep Seedance for people, rooms, camera movement, and environmental footage.
2. Move all information-bearing visuals to deterministic overlays:
   - dashboard UI
   - Copilot interface
   - whiteboard text
   - charts
   - slides
   - subtitles and labels
3. Build those overlays in HTML/SVG/Figma/screenshots and composite them in the final render.
4. Avoid prompt terms that deliberately soften detail when clarity matters:
   - avoid `soft`, `diffused`, `film-like texture`, `indistinct writing`
   - prefer `sharp focus`, `crisp edges`, `large legible text only`
5. Add a quality gate after every generated clip:
   - `media_probe`
   - representative frame extraction
   - reject clips where screens, faces, or foreground subjects are visibly soft.

## Project `93798093580`

### Evidence

Original/primary source asset:

- Asset: `asset://a_uxquaVs`
- Resolution: `1920x1080`
- FPS: `30`
- Video bitrate: about `8.52 Mbps`
- Duration: about `61s`

Intermediate/final 1080p-style asset:

- Asset: `asset://a_iLMbyz1`
- Resolution: `1920x1080`
- FPS: `30`
- Video bitrate: about `10.37 Mbps`

Final render:

- Output file: `pexo_brand_film_4k.mp4`
- Final asset: `asset://a_LWuqhUK`
- `submit_render` used `output_resolution: landscape-4k`
- `submit_render` used `quality: high`

HTML composition evidence:

- Repeated compositions used `data-width="1920"` and `data-height="1080"`.
- The background/source video was also 1080p.

### Root Cause

The final file was branded as 4K, but the pipeline was not true 4K:

- source video: 1080p
- HTML composition canvas: 1080p
- overlays and preview checks: 1080p
- final export: 4K

That creates a fake 4K upscale. The file may be 4K, but the visual information is still 1080p. On top of that, the chain created multiple versions (`v2`, `v3`, `dialogue`, `typewriter`, `v5`, `v6`, `4k`), which increases the risk of generation loss and re-encoding softness.

### Solution

1. If source assets are 1080p, export 1080p.
2. Only export 4K if the entire chain is 4K:
   - original video is 4K
   - HTML canvas is `3840x2160`
   - overlays, image assets, screenshots, and text layout are built for 4K
   - final render is 4K
3. Avoid generation-loss chains:
   - do not render `v2 -> v3 -> v5 -> v6 -> 4k`
   - always return to the original source asset and apply all final overlays in one final composition
4. Keep cards, captions, prompt boxes, and labels as HTML/vector layers in the last render pass.

## Project `06994555780`

### Evidence

Video generation:

- Main clips were generated with `video_generate`.
- Provider/model: `seedance` / `doubao-seedance-2-0-260128`
- Mode: `reference2video`
- Example generated scenes:
  - `seq1_container_port`
  - `seq7_nearshoring_factory`
  - `seq8_digital_supply_visibility`

Source clip probes:

- Generated source clips were `1280x720`
- FPS: `24`
- Bitrate range seen: about `3.8 Mbps` to `5.6 Mbps`
- Clip duration: about `15s`

Composition evidence:

- Initial HTML was authored as `data-width="1280"` and `data-height="720"`.
- Later it was edited toward 1080p output.

Final render:

- Output file: `Supply_Chain_Disruptions_-_Educational_Video.mp4`
- Final asset: `asset://a_uW24zda`
- Resolution: `1920x1080`
- FPS: `24`
- Duration: `241s`
- Video bitrate: about `11.44 Mbps`
- Final successful render used `quality: standard`

There was an earlier `quality: high` render attempt, but it failed lint with issues including:

- `MEDIA_MISSING_DATA_START`
- `OVERLAPPING_CLIPS_SAME_TRACK`

### Root Cause

The final 1080p video was built mostly from 720p generated clips. The final file is 1080p, but the source visual detail is only 720p, so the result looks upscaled and soft.

The issue is amplified by:

- source clips being AI-generated;
- data-heavy scenes such as command centers, maps, dashboards, graphs, and screens;
- a long 241s assembly from a limited set of 15s generated clips;
- final render falling back to `quality: standard`.

### Solution

1. Generate source clips at the target resolution:
   - for 1080p final output, require 1080p source clips;
   - if the model can only produce 720p, export the final at 720p instead of upscaling.
2. Fix HyperFrames lint issues so `quality: high` can be used:
   - add missing `data-start` / `data-duration`;
   - remove same-track overlaps;
   - validate before final render.
3. Avoid asking the video model to synthesize data screens:
   - logistics maps
   - dashboard charts
   - shipment tracking interfaces
   - control-room display walls
4. Render data/UI screens as HTML/SVG/vector overlays.
5. Keep a consistent canvas from the first draft:
   - if the target is 1080p, start with `1920x1080`, not `1280x720`.

## Cross-Project Prevention Checklist

Use this checklist before final delivery for blur-sensitive videos:

1. Confirm source clip resolution with `media_probe`.
2. Confirm source clip resolution is at least the target output resolution.
3. Confirm HTML `data-width` / `data-height` match the intended final output.
4. Confirm final render quality is `high` unless there is a documented reason.
5. Do not upscale 720p to 1080p or 1080p to 4K unless the user explicitly wants an upscale.
6. Keep text, UI, dashboards, maps, tables, captions, and product claims as HTML/SVG/design overlays.
7. Avoid multi-generation render chains. Rebuild from original sources in one final pass.
8. Extract representative frames before final delivery and inspect:
   - faces
   - foreground objects
   - text
   - UI
   - high-detail backgrounds
9. Reject clips where the information-bearing content is generated as mushy texture.

## Recommended Default Policy

For Pexo production, treat AI video generation as best suited for:

- atmosphere
- people
- environments
- camera movement
- emotional context
- non-textural background action

Treat deterministic rendering as mandatory for:

- text
- UI
- dashboards
- charts
- maps
- brand/product claims
- subtitles
- whiteboards
- slides

The reliable pattern is:

> Generate cinematic background video, then composite crisp information layers at final resolution.
