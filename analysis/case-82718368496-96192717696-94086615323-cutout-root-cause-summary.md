# 三个项目抠图处理情况汇总

项目：`82718368496`、`96192717696`、`94086615323`

## 结论

这三个项目里，真正“放弃抠图”只发生在不同阶段、不同原因上：

1. `94086615323` 不是主动放弃，而是先后遇到两类失败：
   - 传入了不可解析的本地路径，`cutout_image` 报 `hyperframes.asset_resolve_failed`
   - 传入了超出限制的 2048x2048 图片，`cutout_image` 报 `hyperframes.invalid_arguments / cutout_validate`
   后面把输入改成 `asset://...` 后，抠图成功了。
2. `96192717696` 没有看到 `cutout_image` 的失败链路，它是直接生成了可用的透明/孤立素材，再进入后续合成。
3. `82718368496` 的最终成片是相册拼贴风格，本来就不是“单主体抠图再贴图”的工作流，所以没有走抠图工具链。

## 为什么有些看起来也该抠的素材没有抠

这三个项目里，抠图不是按“看起来像不像主体”统一执行的，而是按素材角色分流：

- 真正要漂浮到别的底上的单主体，会走抠图
- 贴纸、纸片、票据、涂鸦、边框、装饰件，常常直接当版式元素合成
- 有些素材在生成阶段就被要求成“isolated on white background”或“transparent background”，于是被当作可直接用的孤立素材，没再补一层抠图

所以你看到的“很多明显需要抠图的部分没抠”，本质上不是工具漏跑，而是**流程里没有一条统一的硬判定**。当前实际是混用三种方式：

1. 先抠图再合成
2. 直接生成孤立素材再合成
3. 作为版式组件直接合成，不再抠图

## 根因

真正的根因不是“模型不想抠图”，而是输入和流程不满足 `cutout_image` 的约束：

- 路径必须是可解析的资产引用，不能直接把 workspace 路径当成可用输入
- 图片尺寸必须在工具允许范围内，超限会直接被校验拒绝
- 某些项目的视觉方案本身就不依赖抠图，而是走拼贴、贴纸或直接生成透明素材的路线

## 解决方案

1. 统一把抠图输入转换成 `asset://...` 或可访问的真实资产 URL，再调用 `cutout_image`
2. 对待抠图源图先做尺寸预检，超出范围先 resize，再送入抠图
3. 对拼贴型项目不要强行套“单主体抠图”流程，改为直接生成所需孤立素材或按组件合成
4. 如果后续仍需要透明主体，抠图成功后的结果要在 HTML 里继续用 `asset://...` 引用，别回退成本地路径

## 统一判定建议

- 人物、商品、单独物体，只要最终要悬浮在别的底上，优先走抠图
- 贴纸、票据、撕纸、涂鸦、装饰件、相册框这类版式元素，不必强制抠图
- 对“生成时写了 isolated / transparent background”的素材，要再确认是否真的有 alpha，不要只看提示词
