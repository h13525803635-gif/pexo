# 项目 87181739436：字幕标点与视频生成调度问题分析

## 结论

项目中的“多余标点”来自后期字幕文件，而不是视频模型在底图中随机生成。字幕生成与翻译阶段保留了原稿中的破折号、引号和感叹号；随后字幕按时间切块时没有重新分配跨句标点，合成器又逐字渲染 SRT，最终让句尾破折号看起来像孤立的多余符号。

项目也确实采用了并行视频生成。并行本身不等于叙事不连贯，但当前调度只共享角色参考图，没有把上一镜头尾帧或视觉状态传递给下一镜头。对于需要保持人物姿态、视线、背景位置、光线和运动方向的连续镜头，这种并行策略缺少必要的视觉依赖。

## 一、字幕标点问题

### 1. 直接证据

英语字幕文件中存在以下独立字幕块：

```text
The Bible says —
Matthew chapter 6, verse 22 —
```

泰米尔语字幕中存在对应结构：

```text
வேதாகமம் சொல்கிறது —
மத்தேயு ஆறாம் அதிகாரம் இருபத்திரண்டாம் வசனம் —
```

其他字幕块还保留了引号和较多感叹号，例如：

```text
Friends!
Third — Lot's wife!
God said — "Do not look back!"
```

### 2. 实际处理链路

1. 泰米尔语旁白生成时同步产出带时间码的 SRT。
2. SRT 保留了原始文案中的逗号、句号、破折号和感叹号。
3. 英语字幕按照相同时间段翻译和写入，也复制了相同的语气及连接标点。
4. 长句为了适配语速被拆成多个字幕块，但系统只切分文字，没有判断标点是否依赖下一块。
5. 后期合成器按 SRT 原样渲染，不理解 `—` 是连接下一句的语义符号。

因此，后期程序没有“额外创造”标点，而是忠实显示了上游 SRT 中不适合独立呈现的标点。

### 3. 根因

- 字幕切块以时间和长度为主，缺少句法边界判断。
- 翻译字幕沿用原字幕时间段，未执行目标语言排版规范化。
- 合成前没有孤立标点、重复标点和跨块标点检查。
- 抽帧 QA 只检查字幕是否可见、颜色和位置是否清晰，没有检查文案正确性。

### 4. 解决方案

在字幕写入与视频合成之间增加 `subtitle_normalize` 阶段：

1. 删除字幕块末尾仅用于连接下一句的 `—`，或将其与下一块合并。
2. 禁止破折号、左引号等连接符单独占据一块或停留在块尾。
3. 将成对引号放在同一语义单元内；无法做到时改写为不依赖引号的表达。
4. 将连续感叹号归一为一个，并按语气限制感叹号密度。
5. 对泰米尔语和英语分别执行语言级规范化，不机械复制标点结构。
6. 合成前输出 lint 错误，阻止存在孤立标点的 SRT 进入渲染。

建议 lint 规则：

```text
BLOCK_END_CONNECTOR: 字幕块以 —、-、(、[、左引号结尾
BLOCK_START_ORPHAN: 字幕块以孤立的逗号、句号、右引号开头
PUNCT_ONLY_CUE: 字幕块仅含标点
UNBALANCED_QUOTES: 单个字幕语义单元内引号不成对
EXCESSIVE_EXCLAMATION: 连续感叹号或感叹号密度过高
```

## 二、并行生成与叙事连续性

### 1. 调度证据

三个大段视频任务在 `2026-07-13 06:38:44 UTC` 的同一秒提交：

```text
seg1_intro_scripture
seg2_eve_samson
seg3_lot_closing
```

后续 11 个口型视频片段在 `2026-07-13 07:04:56-07:04:57 UTC` 集中提交，包括：

```text
ls1a, ls1b, ls1c
ls2a, ls2b, ls2d, ls2e
ls3b, ls3c, ls3d, ls3e
```

生成调用均使用 Seedance `reference2video`。每个任务使用同一角色参考图和各自的音频，但未引用上一片段的输出视频或尾帧。

### 2. 为什么系统选择并行

调度器把这些片段识别为“脚本已确定、音频独立、共享角色参考”的无依赖任务，因此优先并行以缩短总生成时间。它认为叙事顺序可以在最终剪辑阶段恢复。

这个判断只保证了内容顺序，不保证视觉状态连续。共享角色参考图能够约束角色身份和大致风格，但不能可靠继承上一镜头的：

- 最终姿态和手势
- 视线与面部表情
- 摄像机位置和运动方向
- 背景人物及物体位置
- 光线、色温和景深
- 运动速度及动作趋势

### 3. 串行并不是所有连贯叙事的必要条件

“叙事连贯”和“生成串行”是两个不同概念。若镜头是不同地点、不同章节或明确跳切，提前规划后并行生成仍可形成连贯叙事。只有当镜头 N+1 必须继承镜头 N 的视觉状态时，才应建立串行依赖。

本项目的问题不是使用了并行，而是没有区分以下两类镜头：

- **语义连续但视觉独立**：可以并行，依靠脚本和剪辑建立叙事。
- **视觉状态连续**：必须串行，或至少使用上一镜头尾帧作为下一镜头参考。

### 4. 推荐的混合调度

三个章节可以并行启动，但每个章节内部应根据连续性串行：

```text
chapter 1: ls1a -> ls1b -> ls1c
chapter 2: ls2a -> ls2b -> ls2c -> ls2d -> ls2e
chapter 3: ls3a -> ls3b -> ls3c -> ls3d -> ls3e
```

具体实施方式：

1. 为分镜增加 `continuity_group` 和 `depends_on` 字段。
2. 对同一连续性组内的镜头，提取上一镜头尾帧并传入下一次生成。
3. 同时保留角色原始参考图，避免连续传递过程中身份逐步漂移。
4. 在 prompt 中显式约束镜头衔接：人物位置、朝向、动作起点、背景和光线。
5. 不同章节或明确转场后的镜头允许并行。
6. 对连续组执行首尾帧 QA，检查角色位置、构图和运动方向是否突变。

推荐任务结构：

```json
{
  "shot_id": "ls2c",
  "continuity_group": "chapter_2_host",
  "depends_on": "ls2b",
  "references": {
    "identity": "eye_character_reference",
    "start_frame": "ls2b.last_frame"
  }
}
```

## 三、修复优先级

### P0：字幕发布前校验

- 上线孤立标点 lint。
- 将 lint 失败设为阻断条件。
- 抽帧 QA 增加字幕文本正确性检查。

### P1：生成任务依赖建模

- 分镜规划阶段标记视觉连续性组。
- 调度器只并行无依赖组。
- 连续镜头启用尾帧传递和原始角色参考双约束。

### P2：质量与性能平衡

- 章节之间并行，章节内部按需串行。
- 记录串行增加的耗时，并以连续性评分决定是否启用。
- 对无需视觉继承的说明性镜头继续使用并行。

## 四、验收标准

字幕验收：

- 成片中不存在单独或悬空显示的破折号、引号及其他连接标点。
- 双语字幕的标点符合各自语言习惯，而不是逐字符镜像。
- SRT lint 为零错误后才能进入最终渲染。

连续性验收：

- 同一连续性组相邻镜头的人物身份、位置、朝向和光线无明显跳变。
- 下一镜头能从上一镜头的动作结束状态自然开始。
- 调度日志能明确展示哪些镜头并行、哪些镜头因 `depends_on` 串行。

## 总结

该项目同时暴露了两个流程缺口：字幕流水线缺少面向画面呈现的标点规范化，视频调度器缺少视觉连续性依赖建模。正确修复不是全面删除标点或全面改成串行，而是在合成前清理不适合独立呈现的标点，并采用“章节间并行、连续镜头内串行”的混合策略。
