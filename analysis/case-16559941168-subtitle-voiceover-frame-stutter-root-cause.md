# 16559941168 成片字幕/旁白错位与画面卡帧根因分析

## 结论

项目 `16559941168` 的问题不是用户脚本错误，而是生产链路在最终装配阶段没有建立可靠的统一时间轴：

- 旁白被拆成 10 段独立 TTS 音频。
- 每段旁白又各自生成 SRT 字幕。
- 最终 HTML 合成没有直接使用这些 SRT 作为单一字幕源，而是把字幕内容二次写入 `<div class="subtitle-line">`，再依赖 `data-start`、全局 offset 和手工替换进行对齐。
- 画面由 10 段 Seedance 背景视频拼进 165.28 秒 HTML 合成，没有看到源视频帧率、时长、可播放时长的统一校验与规整。

因此最终成片会表现为：

1. 字幕文本/出现时间与当前旁白不一致。
2. 背景视频片段播完后停在末帧，或多段 `<video>` 切换时出现停顿、卡帧。

## 根因 1：字幕和旁白缺少单一可信时间轴

链路把旁白切成 10 段后，每段各自生成字幕，再在 HTML 里二次拼接字幕层。这种做法有三个风险：

- 分段字幕的时间戳天然是局部时间，必须准确加上每段在总时间线里的起点。
- HTML 字幕层是人工拼出来的，不是直接从最终主音轨自动派生。
- trace 显示存在 `global offset`、`L02-L10 SUBTITLES` 等后续替换动作，说明字幕时间轴在合成中被二次改写。

只要任一段的偏移、文本复制、段落顺序或累计时长有误，字幕就会和旁白错位。用户看到的“字幕跟旁白完全没有照应”，符合这个链路缺陷。

## 根因 2：短视频素材未按旁白时长规整

画面由 10 段 Seedance 背景视频构成，但最终成片总时长是 165.28 秒。trace 中未看到对这些视频执行以下校验或处理：

- `media_probe` 检查每段真实可播放时长。
- 统一帧率或时基。
- 按旁白段落时长循环、延展、补 B-roll 或重新生成足够长度素材。
- 渲染前做逐段帧缓存/首尾帧检查。

当 HTML 合成中某段视频短于对应旁白段落时，浏览器会停在最后一帧；多段视频切换时也可能因为解码和缓冲造成明显卡顿。这就是“画面卡帧”的主要来源。

## 解决方案

### 1. 改为主音轨优先

不要让 10 段字幕各自成为真源。应先完成全部 VO 合成：

1. 生成分段 TTS。
2. 拼接为单一主旁白音轨。
3. 对主音轨生成全局 SRT/VTT。
4. 最终字幕只从全局 SRT/VTT 渲染。

这样字幕时间戳只对应最终音频，不再需要手工累计 offset。

### 2. HTML 合成禁止手工复制字幕时间轴

最终 HTML 应读取或内联一个由主音轨派生的统一字幕数组：

- 字幕文本、开始时间、结束时间来自同一个全局 SRT/VTT。
- 禁止在 HTML 中手写大量 `subtitle-line` 并二次改 offset。
- 渲染前校验字幕最后结束时间不超过主音轨时长，且首条字幕从 0 秒附近开始。

### 3. 视频素材进入合成前必须 probe

所有背景视频进入 HTML/渲染前，必须记录：

- 宽高与比例。
- fps。
- container duration。
- `video_playable_seconds`。
- 是否有黑帧、静止帧或尾帧冻结。

任一片段短于目标段落时，必须执行以下之一：

- loop 并加轻微缩放/平移避免静止感。
- speed/stretch 到目标时长。
- 生成补充 B-roll。
- 重新生成足够时长的视频。

### 4. 长视频建议先粗剪再渲染包装

对 2 分钟以上课程视频，不建议在 HTML 中直接管理 10 个长时间 `<video>` 源。更稳的路线：

1. 先用媒体处理把各段视频规整为统一 fps、统一分辨率、统一编码。
2. 按旁白段落做粗剪，得到稳定的视频底板。
3. HTML 只负责字幕、标题、少量动效和包装。
4. 最终渲染前抽帧 QA。

### 5. 增加交付前 QA Gate

交付前至少自动检查：

- 主音轨时长与 HTML `data-duration` 差异小于 0.5 秒。
- 字幕总时长覆盖主音轨，且字幕文本片段能在旁白脚本中找到。
- 每个视频段落真实可播放时长覆盖对应时间窗。
- 抽取 0%、25%、50%、75%、95% 帧，检查不是黑帧/重复冻结帧。
- 对最终 mp4 做 `ffprobe`，确认 fps、duration、音轨存在。

## 建议优先级

P0：

- 修复字幕链路：从最终主音轨生成全局字幕，禁止分段 SRT 二次手工拼接。
- 修复视频链路：所有素材进入合成前必须 probe，并处理短素材冻结。

P1：

- 为长视频引入“粗剪底板 + HTML 包装”的生产路线。
- 在 motion render 前增加字幕/音频/视频三方时间轴校验。

P2：

- 保存每次最终 HTML、全局字幕、主音轨和 probe JSON，方便复盘。
