# Pexo 项目 69018917016：相同画面叠加问题复盘

## 结论

相同画面叠加并非 Seedance 原始视频生成异常，而是最终合成阶段重复引用同一个视频素材导致。

合成 HTML 将 `seq1` 至 `seq4` 作为主画面，同时又创建了 `nat1` 至 `nat4` 视频元素来保留环境声。后者虽然设置了 `style="display:none"`，但 Motion 渲染器仍将这些 `<video>` 解析为独立视频轨，最终把同源画面以不同尺寸和位置再次绘制到成片中。

## 用户可见现象

- 钥匙特写镜头出现同一画面的缩放副本，形成规则矩形叠层。
- 年轻夫妇进门镜头出现相同的重复画面。
- 问题出现在多个镜头，且叠层边缘规则，不符合生成模型常见的局部形变特征。

## 根因链路

1. `seq1` 至 `seq4` 在 `data-hf-sequence` 中承担正常可见画面。
2. 为混入原视频环境声，合成代码再次使用相同 MP4 创建 `nat1` 至 `nat4`。
3. `nat1` 至 `nat4` 使用的是 `<video>`，而非真正的 `<audio>` 或渲染器原生音频轨。
4. `display:none` 只表达浏览器 DOM 隐藏意图，不能保证 Motion 的媒体轨解析器不创建视频图层。
5. 渲染前系统检测到 `MOTION_CONTRACT_COVERAGE_AUDIO_OVERLAP`。
6. 提交渲染时通过 `acknowledged_findings` 忽略该警告，异常合成继续执行并交付。

## 解决方案

### 合成实现

- 删除 `nat1` 至 `nat4` 这类用隐藏 `<video>` 模拟音频轨的代码。
- 优先直接启用主序列视频自身的音轨，避免再次引用素材。
- 如果主序列不支持独立混音，先从 MP4 提取音频，再通过 `<audio>` 或 Motion 原生音频轨加入合成。
- 同一个源视频只能有一个可见视频实例；额外引用必须明确声明为纯音频且不进入视觉渲染图。

### 校验与阻断

- 将 `MOTION_CONTRACT_COVERAGE_AUDIO_OVERLAP` 从可确认警告升级为最终渲染的阻断性错误。
- 检测同一 `src` 是否同时用于主画面 `<video>` 和所谓的隐藏音频 `<video>`。
- 禁止使用 `display:none`、`visibility:hidden` 或零透明度作为视频元素“仅音频”的实现方式。
- 如果确需例外，必须验证该媒体节点在渲染器生成的视觉轨列表中不存在。

### 回归验证

- 在每个镜头的开始、中间和转场区间自动抽帧。
- 检测画面中是否存在同源帧的缩放副本、规则矩形叠层或异常画中画。
- 验证成片仍包含预期环境声和背景音乐。
- 断言最终视觉轨只有主序列，音频轨不产生任何可见图层。
- 对项目 `69018917016` 使用修正后的合成文件重新渲染；无需重新生成四段 Seedance 素材。

## 责任层定位

- 原始视频生成：正常，不是根因。
- 合成模板：根因，重复使用 `<video>` 承载环境声。
- Motion 媒体轨解析：未遵循或未明确拒绝隐藏视频的仅音频意图。
- 渲染前校验：发现了音频重叠风险，但允许调用方确认后绕过。
- 成片质检：只检查了片尾文字和安全区，没有覆盖主体镜头的重复图层检测。

## 建议优先级

1. 修正合成模板，移除隐藏视频音频轨。
2. 阻断 `AUDIO_OVERLAP` 风险后继续提交最终渲染。
3. 增加主体镜头抽帧和重复图层检测。
4. 使用原素材重新渲染并核验项目 `69018917016`。
