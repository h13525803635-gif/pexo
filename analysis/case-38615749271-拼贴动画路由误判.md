# Case 38615749271：拼贴动画误路由为 Motion

## 结论

该 case 被判为纯 Motion 不准确。按当前生产路由规范，应该采用 **AIGC 主视觉 + Motion 包装** 的混合路线：Generation 负责生成具有连续动作和材质过程的拼贴画面，Motion 负责精确文字、字幕、CTA、版式、音频同步和最终合成。

推荐的视觉路线是 `aigc_keyframe_whiteboard` 或 `hybrid_aigc_whiteboard_plus_hf_text`，而不是 `hf_dom_only`。

## 用户意图

用户要求一个 20--25 秒、16:9、英文纸张拼贴 stop-motion 教程，主题是使用窗光拍摄食物。关键要求包括：

- 一双手持续重排画面；
- 窗户纸片、盘子、反光板、阴影和相机持续发生动作；
- 反光板需要 hinge，阴影需要滑动和变软，相机需要旋转三个角度；
- 至少三个元素同时运动，并且每秒发生多次可见变化；
- 使用 hard cuts、paper wipes、push-ins 和 parallax tracks；
- 明确禁止 static boards、dissolves 和 fades。

这不是只有标题、图形和卡片变化的 `information_display`，而是以手部重排和纸面物体交互为主要视觉内容的多 beat `process_demo / subject_motion / spatial_motion`。总时长约 22 秒，也超过了纯 DOM 手绘原型的 15 秒上限。

## 根因

根因是路由器把“paper collage”当成了视觉风格判断，而没有优先判断主要视觉是否依赖真实的连续过程运动。

具体表现为：

1. **风格替代了生产路线。** 模型看到 collage、paper、cut-out 后，直接推断 HTML/CSS 可以模拟，而没有先解析 hands rearranging、hinge、rotate、shadow softening 等动作要求。
2. **忽略了多 beat 和时长门槛。** 22 秒、4 个 beat、持续过程动作，不能按短时 `hf_dom_only` 原型处理。
3. **没有区分主视觉和包装层。** 精确标题、字幕和 CTA 确实应该交给 Motion，但这不意味着手部和纸面过程也应由 Motion 伪造。
4. **缺少硬阻断。** 当 brief 同时出现手部/纸面过程、持续交互、`no static boards` 和超过 15 秒时，系统没有阻止 `hf_dom_only`，也没有要求用户确认路线。

## 正确方案

### 路由

```yaml
production_strategy:
  visual_route: hybrid_aigc_whiteboard_plus_hf_text
  generation_role: keyframe_controlled_collage_footage
  motion_role: exact_text_brand_subtitle_and_final_assembly
```

Generation 阶段应按 beat 生成连续的拼贴画面或 keyframe-controlled image-to-video 素材，保持纸面、食物、窗光、反光板和相机的身份与位置连续。

Motion 阶段只负责：

- “MAKE FOOD LOOK DELICIOUS”等精确标题和步骤文案；
- 字幕、CTA 和版式安全区；
- hard cut、paper wipe、push-in、parallax 等包装层；
- 音频同步、最终合成和渲染 QA。

不要让 AIGC 直接生成关键英文文案，因为可读性和字面准确性应由 Motion/HTML 控制。

## 修复要求

**Owner：** Script/router 与 Generation-Motion handoff。

**Trigger：** brief 中同时出现以下任一组信号：

- visible hand / hands rearrange / hand-object interaction；
- stop-motion process、paper/board texture、hinge、rotate、slide、soften 等过程动作；
- `no static boards`、持续运动或多元素同时运动；
- 时长超过 15 秒且有两个或以上 beat。

**Required behavior：** 将主视觉路由为 `aigc_keyframe_whiteboard` 或混合 AIGC 路线，Motion 仅保留精确文字和最终包装。如果用户明确要求 DOM/SVG 原型，才允许覆盖为 `hf_dom_only`，并记录覆盖理由。

**Guardrail：** 若触发上述条件却输出 `visual_route: hf_dom_only`，Script handoff 必须阻断，不能继续进入 Motion；AIGC 路线必须在 trace 中出现对应的 `video_generate` 或 keyframe/image-to-video 证据。

**Regression assertion：** 用本 case 的原始 brief 回归时，handoff 应包含 `visual_route`，值为 AIGC/hybrid；最终 trace 应包含生成视频素材，再由 Motion 完成文字和合成，而不能只有 `edit_file`、`render_frame` 和纯 HTML 渲染链路。

## 置信度与限制

- 路由误判：**confirmed**，由模型自身的路由陈述和后续工具链直接证明。
- 应改为 AIGC 主视觉：**strongly supported**，依据当前 Script/Motion 路由规范及 brief 中的过程运动要求。
- 本报告未重新检查最终 mp4 的画面质量；本次问题是路线选择，不是成片 QA。
